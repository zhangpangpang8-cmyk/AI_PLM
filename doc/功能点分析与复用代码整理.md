# AI_PLM 功能点分析与复用代码整理

> 分析日期：2026-08-25  
> 分析范围：当前仓库前后端源码、SQL 脚本及 `ruoyi-ui/crm功能清单.csv`。  
> 状态口径：**已实现**表示当前代码存在可形成闭环的主要能力；**部分实现**表示只有底座或局部环节；**未实现**表示当前仓库没有对应业务模型、接口和页面。

## 1. 系统现状

当前系统是基于 RuoYi 3.9.2 扩展的 PLM 应用，核心是项目、物料、BOM、文档和审批流程；CRM 功能清单描述的是后续“销售—财务—生产—供应链—AI”一体化蓝图，两者的业务范围差异很大。

### 1.1 已有业务模块

| 模块 | 当前能力 | 主要代码 | 完整度与问题 |
|---|---|---|---|
| 项目概览 | 项目 CRUD、审核、项目统计、关联项目经理 | `PjOverview*`、`views/system/overview` | 基础闭环已具备；项目分类查询值与编辑值口径不一致；流程审批和直接审核两条路径并存 |
| 项目阶段 | 阶段实体、Mapper、Service、Controller CRUD | `PjPhase*`、`views/system/phase` | **前后端严重错配**：后端字段为 `phaseCode/phaseName/planStartDate`，前端仍使用 `taskCode/taskName/startTime/assigneeName`，当前页面不能视为可靠完成 |
| 项目任务日志 | 进度前后值、工时、工作内容、问题记录 CRUD | `PjTaskLog*`、`views/system/log` | 可作为项目过程留痕基础；缺少任务主数据与阶段闭环 |
| 物料分类 | 多级分类、树查询、参数与 MES 同步标识 | `ProMaterialClassify*`、`views/system/classify` | 基础能力较完整；应增加编码唯一性、父子删除约束和循环引用校验 |
| 物料管理 | CRUD、分类、供应商文本、审核、审批流、版本快照、分类统计 | `ProItem*`、`ProItemVersion*`、`views/system/item` | 是当前完成度最高的业务模块；供应商仍不是独立主数据；审批与版本逻辑耦合在流程任务服务中 |
| BOM | BOM 与物料/产品关联、层级、用量、版本说明 CRUD | `ProItemBom*`、`views/system/bom` | 有结构字段但主要是平面 CRUD；缺少整树加载、替代料、损耗率、生效范围、变更比较和齐套计算 |
| 图纸管理 | MinIO 上传、元数据、项目/任务关联、审批状态 | `DmDrawing*`、`views/system/drawing` | 新增上传与审批基础存在；编辑接口不支持替换文件，删除数据库记录时未同步清理对象存储 |
| 技术文档 | MinIO 上传/替换、自动发起审批、版本递增 | `DmTech*`、`views/system/tech` | 有审批闭环；任何修改都会递增版本，审批回写也可能触发版本递增；异常日志仍使用 `System.out` |
| 测试报告 | BOM 关联、环境、软硬件、工具、结果与结论 CRUD | `DmTestReport*`、`views/system/report` | 基础 CRUD；未看到自动审批、附件、测试项明细和缺陷关联 |
| 审批流程 | 定义、节点、连线、设计器、发起、待办、已办、业务状态回写 | `WfProcess*`、`views/system/process` | 当前引擎只创建第一个任务，任一审批后直接结束实例；未真正执行后续节点、条件分支、会签、转办和退回 |
| 权限与审计 | 用户、部门、岗位、角色、菜单/按钮权限、数据范围、操作日志 | RuoYi `Sys*` 与 framework | 平台底座较完整；新增业务仍需逐模块补充数据范围过滤 |
| 通知公告 | 公告、已读记录、顶部列表、全部已读 | `SysNotice*` | 支持站内公告，不等同于业务事件驱动的消息中心 |
| 通用平台 | 字典、参数、代码生成、Excel 导出、监控、Redis、定时任务 | RuoYi 通用模块 | 可复用于后续 CRM 模块 |

### 1.2 数据库脚本现状

仓库 SQL 只明确包含 RuoYi 基础表、`sys_drawing` 和单独的 `pro_item_version` 脚本。当前 Java/MyBatis 已引用的项目、BOM、技术文档、测试报告和流程表，并未在一份完整、按版本排序的迁移脚本中统一出现。这会导致新环境无法仅依靠仓库稳定还原数据库。

建议新增 Flyway/Liquibase，至少按以下边界整理迁移：

1. `V1__ruoyi_base.sql`
2. `V2__plm_project.sql`
3. `V3__plm_item_bom.sql`
4. `V4__plm_document.sql`
5. `V5__workflow.sql`
6. `V6__indexes_constraints_seed.sql`

## 3. 已整理的复用代码

### 3.1 前端标准 CRUD 请求

新增 `ruoyi-ui/src/api/crud.js`，统一若依常用 REST 约定：列表、详情、新增、修改、删除，并支持为上传等操作注入额外 axios 配置。

已接入：

- 项目概览、项目阶段、任务日志
- 物料、BOM、物料分类
- 图纸、技术文档、测试报告
- 流程定义

各页面原有命名导出保持不变，因此页面调用方无需修改。

### 3.2 业务枚举

新增 `ruoyi-ui/src/constants/business.js`，集中维护流程分类、流程类型、启停状态和审批人类型。流程定义页与流程设计器不再分别硬编码相同选项。

后续应继续迁移的枚举：项目状态、优先级、发布状态、审核状态、物料启停、文档类型。若枚举需要管理员在线维护，应改用 RuoYi 数据字典，不应继续扩展常量文件。

### 3.3 文件元数据

在 `FileUploadUtils` 中新增统一的文件大小格式化方法，并让图纸和技术文档上传统一复用文件后缀与大小计算。图纸新增时同时补齐 `size/fileSuffix/fileSize`。

### 3.4 暂不抽成运行时泛型基类的代码

Controller、Service、Mapper 中的 CRUD 样板虽然重复，但它们包含不同的权限表达式、Excel 泛型、事务、审批启动、版本快照和统计逻辑。强行使用反射或泛型基类会隐藏业务差异。建议在 RuoYi 代码生成模板中统一，而不是让线上运行时代码承担抽象成本。

## 4. 关键问题与优先级

### P0：影响功能正确性

1. **项目阶段前后端字段完全不匹配**：应确定页面到底是“阶段”还是“任务”，然后统一实体、表、Mapper、接口和页面字段。
2. **流程只执行第一个任务**：审批后直接把实例设为完成，设计器中的后续节点与条件连线不会执行。
3. **数据库迁移不完整**：新环境无法从仓库脚本可靠建出当前业务表。
4. **技术文档审批回写可能再次递增版本**：`updateBusinessStatus()` 调用 `updateDmTech()`，而后者对任意修改自动加版本。

### P1：数据与安全风险

1. MinIO 和 JWT 使用固定默认凭据，应迁移为环境变量，生产环境必须更换。
2. 文件删除只删数据库记录，未删除 MinIO 对象；上传成功后数据库失败也会留下孤儿文件。
3. 多处使用 `System.out/err`，应统一为 SLF4J，并避免输出文件 URL、业务敏感数据。
4. 业务表需补唯一约束、外键/逻辑约束、状态检查和常用查询索引。
5. 流程业务状态回写使用长 `if/else` 并直接依赖多个业务 Service/Mapper，后续应改为按 `businessType` 注册处理器。

### P2：可维护性与体验

1. 多个 Vue 页面超过 500 行，流程设计器超过 1500 行，应拆为查询区、表格、编辑表单、详情、选择器和画布子组件。
2. 项目状态、流程状态、发布状态在多个文件硬编码，应逐步迁移到共享常量或数据字典。
3. API 错误处理、上传进度、取消请求和空状态展示需要统一。
4. 当前没有自动化测试；至少应覆盖流程推进、版本递增、文件元数据、项目/物料审批和 Mapper SQL。

## 5. 推荐实施顺序

1. 修复项目阶段字段错配，补齐业务表迁移和基础测试。
2. 将流程引擎改为“节点推进器”，支持查找下一节点、条件分支、多人审批和幂等审批。
3. 完成客户、联系人、商机、报价、合同、订单主链（MK-01～10）。
4. 建立库存、采购、生产计划和履约事件链（MK-25～40）。
5. 建立统一事件、消息、预警、工单和协同工作台（MK-48～54、64、69）。
6. 在数据链稳定后再建设预测、推荐、仿真和模型管理（MK-11～18、41～47、55～63、71）。

## 6. 新模块复用规范

新增一个标准业务模块时，建议统一包含：

- 后端：Domain/DTO/VO、Mapper、Service、Controller、权限标识、操作日志、数据范围、校验、迁移脚本、测试。
- 前端：使用 `createCrudApi` 的 API 文件、数据字典/共享枚举、列表页、编辑组件、详情组件、权限按钮。
- 集成：幂等键、来源系统、外部 ID、同步版本、最后同步时间、同步状态和错误原因。
- 审计：创建/修改人时间、业务状态历史、字段变更历史、流程实例和消息事件。
- AI：训练数据版本、特征版本、模型版本、预测时间、置信度、解释、人工反馈和实际结果回填。
